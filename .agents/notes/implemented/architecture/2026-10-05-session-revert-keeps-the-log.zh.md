# Agent Note: 会话撤回隐藏日志行，而不删除它们

Status: implemented

[English](2026-10-05-session-revert-keeps-the-log.md) | 中文

## 问题

撤回必须让一条用户消息及其后的内容离开下一次模型请求。会话日志同时又是该请求的唯一重建来源。删掉这些行，之后的读者就无法显示被撤回的内容，并且需要新的日志代际。旧读者如果跳过标记，仍会把隐藏的消息发出去。

## 决定

`session/revert/staged`、`session/revert/cleared` 和 `session/revert/committed` 作为必需事件留在日志里。`Session.deriveMessages()` 省略暂存序号及其后的全部事件，并省略每个已提交区间直到提交事件为止，不包含提交事件。这些行本身保留。文件回滚不在日志里：`@lulu-ling/dsh-session-file-snapshot` 把 git 树存在用户仓库之外，并在 stage 或 clear 时恢复。

## 影响

不认识这三种事件的构建会拒绝包含它们的日志。第一次撤回之前的日志仍可打开。重新加载会话时，消息边界从日志恢复。文件只有在同一台机器上的快照目录还在时才会恢复。捕获是每个回合一次，发生在第一次 pre-step，不是每个 step 一次。

## 曾考虑的替代方案

- **下一条 prompt 发出时删除隐藏的消息。** 这与 opencode 的 cleanup 路径一致。这里没有采用，因为本 harness 从日志重建模型历史，删除会丢掉被撤回回合的唯一副本。
- **把事件标成 `ignorable: true`。** 更旧的读者会跳过它们，并把隐藏的消息发出去。该标记只用于丢失后不会改变重建结果的记录。
- **只把边界留在内存里。** 重新加载后，被撤回的消息会再次出现，包括出现在模型请求里。
